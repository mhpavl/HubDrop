# HubDrop design

Last updated 2026-10-19.

## Why

Xcode 27 replaced Simulator.app with Device Hub. Device Hub has no UI for adding photos or videos to a simulator's Photos library, and the only way to do it is:

```
xcrun simctl list devices booted
xcrun simctl addmedia <udid> ~/Pictures/sample.heic ~/Movies/clip.mp4
```

Seeding test media is a daily task when building an app that imports photos or video, especially across several simulators (iPhone, iPhone Duo, iPad, Vision Pro), so HubDrop makes it a drag to the menu bar.

## What was ruled out

- **Xcode extension.** XcodeKit only offers source editor extensions. They read and modify text in the editor and cannot add UI to Device Hub. Verified against the XcodeKit docs on 2026-10-10.
- **Physical devices.** `devicectl` has no `addmedia` equivalent. `devicectl device copy` only writes into an app's container. HubDrop is simulators only.
- **SwiftUI `MenuBarExtra` for the icon.** It does not expose the underlying `NSStatusItem`, so there is no way to accept a drop on the icon itself. HubDrop creates its own `NSStatusItem` in AppKit and hosts the SwiftUI panel in an `NSPopover`.

## Behaviour

- Drop files on the menu bar icon. They are added to every booted simulator. The icon highlights during the drag and flashes a checkmark for two seconds on success.
- Click the icon to open the panel. A segmented control switches **Send to** between **All Booted** and **Selected**. In Selected mode each simulator row gets a checkbox. Selected simulators that are shut down are booted first with `simctl bootstatus -b`, which blocks until the device is ready.
- The panel also has a drop zone, a refresh button, the last result line, a Launch at Login checkbox, and Quit.
- Quit is a plain `NSApp.terminate`. On macOS 27 that logs one line per run: ``-close` should not be called on windows that the application did not create or own``. It is AppKit talking to itself: `terminate:` sends `_closeForTermination` to every window in the app's window list, and the popover's private window class warns unconditionally on any `-close` before forwarding to its popover. Closing or releasing the `NSPopover` first does not help, because its window is only ever ordered out and stays in the window list (verified by disassembly on 2026-10-19). The only fix is to stop using `NSPopover` and host the panel in an app-owned `NSPanel`. Until that is worth doing, the line is accepted and should be reported to Apple.
- Dropping a folder adds every image, movie, and vCard at its top level, sorted by name. Nested folders are not descended. Live Photo HEIC and MOV pairs are matched by `simctl` itself.
- On failure the icon shows a warning glyph and the panel opens with the text `simctl` printed.
- The app is an agent (`LSUIElement`), so no Dock icon. Cmd-comma opens a small Settings window with the Launch at Login toggle and a one-line usage hint, because a SwiftUI `App` needs at least one scene.

## Files

All in `HubDrop/`. The target uses a file-system-synchronized group, so new files in this folder join the target automatically.

| File | Responsibility |
|---|---|
| `HubDropApp.swift` | `@main` App. Installs `AppDelegate` via `@NSApplicationDelegateAdaptor`. Its only scene is `Settings`. |
| `AppDelegate.swift` | Creates the `NSStatusItem`, the `NSPopover` hosting `DropPanel`, and the `StatusItemDropView`. Flashes result glyphs on the icon. Owns the single `HubDropModel`. |
| `StatusItemDropView.swift` | `NSView` subclass added as a subview of the status bar button. Registers for `.fileURL` drags, highlights the button while a drag hovers, forwards clicks to the button with `performClick`. |
| `HubDropModel.swift` | `@Observable` app model. Simulator list, target mode, selected UDIDs (persisted in `UserDefaults`), busy flag, last `Outcome`, Launch at Login via `SMAppService.mainApp`. `add(_:)` filters the drop to media files, boots targets as needed, calls `simctl`, and reports through the `feedback` closure. |
| `SimulatorService.swift` | Stateless `simctl` wrapper. `listSimulators()` parses `simctl list devices -j` and keeps available iOS and xrOS devices, booted first. `boot(_:)` and `addMedia(_:to:)`. The private `run(_:)` spawns `/usr/bin/xcrun`, drains stdout and stderr concurrently so a large JSON payload cannot stall the child, and throws `CommandFailure` with the tool's output on a non-zero exit. |
| `DropPanel.swift` | The SwiftUI panel. Fixed width 320. Simulator list height is computed from the row count and capped at 200 so the popover sizes itself. Uses `dropDestination(for: URL.self)`. |
| `Assets.xcassets` | Accent colour only. The app icon is not here. |
| `AppIcon.icon` | Icon Composer file. `icon.json` stacks five flat layer PNGs in `Assets/` into three Liquid Glass groups: a badge on top, the three devices, and the blueprint grid underneath. The layer PNGs are generated by `Scripts/make-icon.swift`; edit the script and rerun it rather than touching the PNGs, and adjust glass, blend, and translucency in Icon Composer, which rewrites `icon.json`. The design follows Device Hub's: translucent glass phone, tablet, and Vision Pro shapes over a grid, plus a blue plus badge bottom right to match the `photo.badge.plus` menu bar glyph. The system renders every size and the dark and mono variants at build time. |

## Build settings the target needs

The source is written against these. Set them on the HubDrop target after creating the project.

| Setting | Value | Why |
|---|---|---|
| `MACOSX_DEPLOYMENT_TARGET` | 26.0 | Runs on Tahoe and Golden Gate. |
| `ARCHS` | arm64 | Apple silicon only. Xcode 27 and its simulators do not run on Intel, so a universal release build would only add size. |
| `SWIFT_VERSION` | 5.0 | Swift 6 mode would turn a few Sendable warnings into errors. Approachable concurrency and MainActor isolation give most of the benefit without them. |
| `SWIFT_APPROACHABLE_CONCURRENCY` | YES | Same reason. |
| `SWIFT_DEFAULT_ACTOR_ISOLATION` | MainActor | The model, delegate, and views assume it. `SimulatorService.run` and the media filter are explicitly `nonisolated`. |
| `SWIFT_UPCOMING_FEATURE_MEMBER_IMPORT_VISIBILITY` | YES | The Swift 6 default. Each file must import what it uses rather than relying on transitive imports. |
| `GENERATE_INFOPLIST_FILE` | YES | No Info.plist file in the repo. |
| `INFOPLIST_KEY_LSUIElement` | YES | Menu bar only, no Dock icon. |
| `INFOPLIST_KEY_LSApplicationCategoryType` | public.app-category.developer-tools | |
| `ENABLE_APP_SANDBOX` | NO | The app spawns `xcrun`. Remove the template entitlements file or clear `CODE_SIGN_ENTITLEMENTS`. |
| `ENABLE_HARDENED_RUNTIME` | YES | Fine with child processes. Needed for notarisation later. |
| `PRODUCT_BUNDLE_IDENTIFIER` | com.flixel.HubDrop | The `os.Logger` subsystem strings use this. |
| `DEVELOPMENT_TEAM` | 8D2X524S6C | The maintainer's team, automatic signing. Contributors pick their own in Signing & Capabilities. |
| `ASSETCATALOG_COMPILER_GLOBAL_ACCENT_COLOR_NAME` | AccentColor | |

`ASSETCATALOG_COMPILER_APPICON_NAME` must be `AppIcon`, matching the Icon Composer file's name without its extension. It is the App Icon field in the target's General tab. The xcode-tools build-setting tool does not recognise this setting, so it has to be set from Xcode's UI.

## Distribution

HubDrop ships outside the Mac App Store as a notarized Developer ID build. The App Store is not an option because the app is unsandboxed.

- `Scripts/release.sh` does the whole release: `xcodebuild archive` of the Release configuration, `xcodebuild -exportArchive` with `Scripts/ExportOptions.plist` (method `developer-id`, automatic signing, team 8D2X524S6C), `notarytool submit --wait`, `stapler staple`, then a `ditto` zip named `HubDrop-<version>.zip`. Pass `--skip-notarization` to stop after the signed export.
- Notarization credentials live in the keychain under the `notarytool` profile `HubDrop`. The script's header shows how to create it from an app-specific password or an App Store Connect API key.
- The project's own `CODE_SIGN_IDENTITY` stays `Apple Development` in every configuration. The export step re-signs with Developer ID, so a Debug run and a release build differ only in optimisation. The hardened runtime is on for both, and the app needs no runtime exceptions: spawning `xcrun` and `SMAppService` both work under it.
- Releases are zips rather than DMGs. A zip needs no extra signing step and Safari unpacks it on download. Revisit if an installer experience is ever wanted.
- The repository is public under the MIT license. Nothing in it is secret: the team identifier appears in every signed binary anyway, and notarization credentials never touch the repo.

## Verifying a run

```
xcrun simctl list devices booted
```

Boot an iPhone simulator, drop a HEIC and an MP4 on the icon, then open Photos in the simulator. Both should be in Recents. Check `Console.app` for subsystem `com.flixel.HubDrop` if anything is unclear.
